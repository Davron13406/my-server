# FitQuest 2.0 — Python edition

Серверная часть перенесена с Node.js/Express на **Python + Flask**. Интерфейс HTML/CSS/JavaScript и схема PostgreSQL сохранены, чтобы не переписывать внешний вид и клиентскую логику без необходимости.

## Запуск на Windows 11

1. Установи Python 3.11+ и Docker Desktop (если запускаешь через Docker).
2. Открой PowerShell в папке `FitQuest_Platform`.
3. Выполни:
   ```powershell
   docker compose up --build
   ```
4. Открой `http://localhost:3000`.
5. Остановка: `Ctrl+C`; затем `docker compose down`.

## Запуск без Docker

Нужен PostgreSQL 16+ с созданной базой `fitquest`.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Отредактируй `.env`, указав правильный `DATABASE_URL` и длинный случайный `SESSION_SECRET`. Затем создай таблицы:

```powershell
psql "$env:DATABASE_URL" -f db/schema.sql
py server.py
```

Если PowerShell запрещает активацию окружения, можно запускать pip и Python напрямую:
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

## Что сохранено

- прежний интерфейс и PWA-файлы;
- PostgreSQL и таблицы из `db/schema.sql`;
- регистрация, вход/выход, профиль, магазин, экипировка;
- запись тренировок с UUID-защитой от повторного начисления;
- программы и последовательное прохождение дней;
- GPS-точки с базовой проверкой точности, времени и скорости;
- таблица лидеров и основные API-маршруты.

## Важные замечания

- `server_nodejs_original.js` оставлен как резервная копия прежнего сервера.
- Клиентский `public/app.js` по-прежнему написан на JavaScript — это нормально: Python заменяет сервер, а браузерный интерфейс остаётся на HTML/CSS/JS.
- Содержимое отдельных курсов в Python-версии пока возвращает нейтральную заглушку; исходный подробный каталог курсов нужно отдельно перенести, если он нужен в приложении.
- Перед публикацией замени секрет сессии, настрой HTTPS, резервные копии и проверь CORS/CSRF и ограничения запросов.
- Выполни проверку на своей машине с PostgreSQL: этот архив подготовлен, но интеграционный запуск с реальной БД здесь не проводился.


## Облачный запуск 24/7 (Render)

В корне добавлен `render.yaml`. Он описывает Python web service и PostgreSQL. Чтобы сервис не засыпал, в Blueprint указаны платные планы Render: web `0.5c-512mb` и PostgreSQL `0.1c-256mb`. По текущему прайсу это ориентировочно от **$7 + $6 = $13 в месяц**, без возможных дополнительных расходов и налогов; цены могут меняться. Бесплатный web service засыпает после 15 минут бездействия, а бесплатная PostgreSQL-база действует только 30 дней, поэтому бесплатный вариант не соответствует требованию 24/7.

Порядок публикации:
1. Создай репозиторий GitHub и загрузи в него содержимое папки `FitQuest_Platform` (не ZIP-файл).
2. В Render выбери создание Blueprint и подключи этот репозиторий.
3. Проверь конфигурацию и стоимость ресурсов до подтверждения. Для платной публикации попроси родителя/опекуна помочь с аккаунтом и оплатой.
4. После развёртывания Render покажет публичный HTTPS-адрес вида `https://...onrender.com`.
5. Открой адрес и проверь `/api/health`. Затем используй этот адрес для Android-клиента: APK, который открывает локальные файлы внутри WebView, нужно отдельно перенастроить на размещённый HTTPS-сайт и пересобрать.

Важно: публикация в облако не выполняется автоматически из этого архива. Нужны аккаунт хостинга и загрузка исходников в GitHub. Перед реальным использованием проверь регистрацию, вход, сохранение тренировок и работу GPS на телефоне. Не загружай в публичный репозиторий `.env`, пароли или секреты.
